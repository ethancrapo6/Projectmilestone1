Birth of the Web Server

In 1989, the World Wide Web (WWW) was invented by Tim Berners-Lee, who is a British scientist. He developed the idea while working at CERN. He designed the Web so that scientists from universities and research institutions all over the world could easily communicate with each other and share their work.

At the end of 1990, Berners-Lee made the first web server and web browser at CERN. His first web server was installed in his office on a NeXT computer. Info.cern.ch was the first website. This website described the World Wide Web project. The site also gave an explanation of what hypertext was, explained how to set up your own web server, and eventually pointed users to other websites.

Early Web Servers

Early after CERN’s first web server was built, with the growing interest in the World Wide Web, web server software began to spread. In 1991, Tim Berners-Lee released his WWW software, which included web server software, a browser, and developer tools. The first web server in North America was then set up by the Stanford Linear Accelerator Center (SLAC) in California in late 1991. Over the next few years, the Web exploded. At the beginning of 1993 CERN made all of its World Wide Web software free. This allowed other organizations around the world to develop and host their own sites on the Internet. By the end of 1993 there were over 500 web servers in operation. And by the end of 1994 this number had grown to nearly 10,000 servers.

The second major player to appear in the early days of the web server market was NCSA HTTPd. Developed at the National Center for Supercomputing Applications (NCSA), NCSA HTTPd quickly became the leading web server software of its era, providing much of the architecture upon which future versions of the Apache HTTP Server would be based.

  • 1990: First web server at CERN
  • 1991: WWW server software released
  • 1991: First U.S. web server at SLAC
  • 1993: CERN makes its web software free
  • 1994: Nearly 10,000 web servers in operation
  • 1995: Apache arrives

Growth of the World Wide Web

The Web Reaches More Users: During the late 1990s, the World Wide Web experienced exponential growth due to the increasing availability of Internet connections to the general population. With easy-to-use graphical browsers (such as Netscape Navigator), the web was no longer limited to university campuses and research organizations but could be accessed from home and/or in businesses.

Growing Demands on Web Servers: As the number of sites on the Internet grew, so did the number of visitors. This increased both the amount of data that had to be processed by web servers and the complexity. The need for dynamic and database-driven content is now being met through the inclusion of images, interactive elements, databases, and dynamically generated content. Before these additions, web servers were limited to providing only static documents and other forms of basic content.

Web Servers Evolve:As websites became more complex, web servers had to support more than just basic HTML pages. New technologies allowed servers to communicate with databases, generate dynamic content, and handle increasing numbers of visitors. These improvements helped establish the foundation for modern web servers, which are designed to deliver websites efficiently, securely, and reliably.

Evolution of HTTP

HTTP/0.9 (1991): The original version of HTTP was very simple in terms of functionality and was used primarily for retrieving HTML pages. The client would send a request for a specific page to the web server and then the web server would provide the requested page back to the client. This early version of HTTP had no HTTP header support; it had only GET support and there were no status codes available to help indicate how successful the request and response processes were.

HTTP/1.0 (1996): In comparison to HTTP/0.9, HTTP/1.0 expanded upon this base model so that it could support retrieval of other content in addition to HTML. In addition to expanding what type of content can be retrieved from the internet, HTTP/1.0 also added HTTP headers and status codes to provide the client with more detailed information about both the request process and the response process. However, an important limitation of HTTP/1.0 is that every time a user requested a new page, a new connection to the server was made (regardless if that page included links). As users began requesting pages that included links to other pages (which are often referred to as hyperlinks), this caused a lot of inefficiencies with regards to making requests for new pages because the browser needed to make a new connection to the server before it could start processing that second page request.

HTTP/1.1 (1997): One of the primary ways in which HTTP/1.1 improved upon the limitations of HTTP/1.0 is that it allowed clients to reuse a single connection to make subsequent requests. The introduction of persistent connections in HTTP/1.1 greatly enhanced the overall performance of browsing the web as it reduced the overhead associated with creating a new connection for each page request. Also, in addition to improving performance through persistent connections, HTTP/1.1 introduced many of the standards that enabled the rapid growth of the World Wide Web into what we know today.

HTTP/2 (2015): As the web continued to grow, modern websites have become increasingly complex, resulting in a need for better performing protocols. One of the main goals of developing HTTP/2 was to improve performance by enabling clients to transfer multiple requests and responses across a single connection at once, thus eliminating the need for each individual request to wait until all of the prior requests had been completed. This goal was accomplished by introducing multiplexing into the HTTP/2 protocol.

HTTP/3 (2022): Another major development in the evolution of HTTP has been the transition from TCP to QUIC as the transport layer protocol for HTTP. While TCP continues to perform well under most normal circumstances (i.e., a continuous network connection), there are certain cases where the performance characteristics of TCP result in suboptimal results such as when the network connection experiences packet loss or congestion, or when there is a delay in establishing a connection due to DNS lookups, etc. These issues resulted in researchers looking for alternative solutions to TCP and ultimately led to the development of QUIC.
